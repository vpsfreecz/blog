vpsAdmin now lets you boot a VPS from a clean template system, bypassing the system on its disk. It is something like booting a live CD.

This lets you access the VPS disk from outside its installed system. It is useful if the VPS will not start and you need to fix a configuration file, the package system or anything else. It is also a way to install any system beyond the distribution templates available in vpsAdmin.

A VPS started in rescue mode has exactly the same configuration: IP addresses, hostname, DNS resolvers, features and so on. If you have SSH keys configured in vpsAdmin, those are uploaded too.

You can start a VPS in rescue mode from its details using the "Boot VPS from template" form, or directly from the remote VPS console page. By default, the original VPS disk is mounted at `/mnt/vps`. Restarting the VPS by any means leaves rescue mode and boots it from its own disk again. The system used for rescue mode is temporary and deleted after a restart.

Rescue mode is only for VPSes on vpsAdminOS. On OpenVZ Legacy, we support a different approach: one VPS's dataset can be mounted in another VPS, so a production VPS can be repaired from playground, for example. We lost that option on vpsAdminOS, and it is now returning in a different form. Personally, I like this approach much more.

In the future, I would like to add an option to vpsfreectl to restore a VPS from a downloaded backup through rescue mode, including its vpsAdmin settings. You can already use rescue mode to restore a downloaded backup, though. Just copy the backed-up system into /mnt/vps.

For more information on repairing a broken VPS and screenshots, see the knowledge base.
