We have prepared several technical updates for vpsAdmin. You can view SSH host key fingerprints, control changes made to template settings, and we are beginning the move to new cgroups.

SSH key fingerprints

The VPS details in vpsAdmin now show SSH host key fingerprints. When connecting over SSH for the first time, you can check the server's identity. Fingerprints are read from the VPS's /etc/ssh/ssh_host_*.pub files after every VPS start and then once an hour.

VPS changes by vpsFree administrators

The distribution templates used to create new VPSes may contain settings specific to our environment. A bug or new feature in an application or our environment may require a system configuration change. This concerns almost exclusively the base system: settings included in the templates.

You can choose in vpsAdmin whether you want these changes. They are enabled by default. If we change anything inside your VPS, we will notify you by email.

For example, we recently removed the cglimit cgroup from the kernel. It was our own controller and turned out to be unnecessary. Distributions with systemd handled this themselves, but Alpine/Devuan/Void, for example, list cgroups in an init script, so we had to change that in existing VPSes.

cgroups v2

This year, we would like to begin the move to cgroups v2. Linux uses cgroups to account for and limit groups of processes. In our environment, they are a basic mechanism for isolating VPSes, used mainly to limit memory and CPU time. Naturally, all container solutions, including the popular Docker, build on cgroups.

We currently use cgroups v1 in a hybrid hierarchy. Since our VPSes are containers, the cgroup version is determined by the host. In 2024, systemd will probably stop supporting cgroups v1, and we want to be ready. Current distributions already support v2; older ones such as CentOS 7 will continue to run on nodes with v1.

In vpsAdmin, you can set which cgroup version a VPS requires. By default, this follows the distribution template. If applications in your VPS have special requirements, you can force cgroups v1 and prevent a future migration to v2. Our aim is to move everything we can to cgroups v2. More information and a list of distributions supporting cgroups v2 are in the knowledge base.

This requires no action from you. We will notify you individually about any move of your VPS to cgroups v2 in the coming months.
