We currently back up once a day using rsync. But we are preparing a move to ZFS snapshots, which will open up many possibilities.

After rsync finishes, a snapshot preserves the resulting state. Backups run automatically once a day and cannot currently be configured for individual VPSes. You can then access backups through the control panel or directly from your VPS in /vpsadmin_backuper and its .zfs/snapshot/ subdirectory. Read more in our knowledge base.

Our developer Jakub "Aither" Skokan is already working on a complete rewrite of vpsAdmin (our web interface), which will use ZFS snapshots and send/receive instead of rsync. Snapshots will be taken locally (and quickly) on the physical server, then all sent to the backup server at night. This will give us many more options for working with backups.

It will be possible to configure the snapshot interval and retention for each VPS, as well as take a snapshot on demand at any time through an API call (which, thanks to HaveAPI, means a single vpsfreectl command). We will write more about that when we deploy it.

ZFS snapshots are "free" in terms of performance and are instantaneous. Essentially, the only drawback, and the reason we cannot take them every 500 ms, for example, is that a snapshot forces the dataset's state to sync to disk. We would be syncing constantly, which would kill disk performance. I expect the minimum interval configurable for backup snapshots to be 15 minutes. But as I said, you will be able to take a backup manually at any time.

The upcoming vpsAdmin 2.0 has three "knobs" for setting snapshot lifetimes:

  • the minimum number of snapshots to keep (to be set to 14)
  • the maximum number of snapshots (initially 20)
  • the maximum snapshot age (14 days)

That allows up to six additional snapshots taken manually without starting to delete the oldest automatic backup snapshots. Excess snapshots will then be deleted during the nightly transfer to the backup server.

One important change, though, is that backups will no longer be as easily accessible inside a VPS. This is because vpsAdmin 2.0 will support subdatasets, and rolling back to a particular snapshot deletes all newer snapshots. We therefore need branching, which is described in detail in the documentation.

At the moment, we estimate that vpsAdmin 2.0 will be ready towards the end of the year. We hope to deploy it around Christmas.
